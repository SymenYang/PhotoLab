# 全局模型生命周期

所有入口通过 `SemanticWorker` 路由到 `ModelService`，使用相同的队列、取消和空闲机制。进程范围是一个 PhotoLab 应用进程：不同应用进程（包括隔离测试）各自拥有服务。

- SigLIP 索引、单模型检索、相似分组和混合检索共享一个 SigLIP Engine。
- Qwen 索引、单模型检索和混合检索共享一个 Qwen Engine，保留现有 Core ML 图像路径、Transformers 文本路径及回退逻辑。
- 美学、画质、自动裁剪、手动裁剪评分共享一个 Q-ReAlign 模型；IAA/IQA 只切换提示词及模型缓存标识，数据库隔离。
- Python 依赖环境不同，因此实际使用 embedding 与 art 两个运行进程；两者使用同一服务实现，按模型用途设置生命周期，并非每个功能各开一个模型进程。

应用启动后通过共享调度器分别发送 SigLIP 和 Qwen 的 preload 请求，即使图库为空也加载两者权重；加载失败会记录日志，后续使用仍可重试。艺术/质量模型首次真正需要推理时加载权重。status/已有分数读取不加载权重；参考照片已有有效向量时，以图搜图和混合排名融合不加载权重。文字查询只在查询向量缓存未命中时编码；单模型与混合检索共享文字向量缓存（每模型最多 32 条）。模型释放/进程结束后，文字缓存失效；照片 embedding 持久缓存仍保留。

请求按优先级排队：文字/手动交互 > 自动裁剪 > 批量索引；同优先级 FIFO。每个运行进程同时处理一个请求，不中断已启动的 GPU 推理。取消排队请求会立即丢弃；取消正在进行的请求会等当前推理返回，让索引调用者记账已经提交的结果，随后停止后续工作。裁剪调用者会丢弃已取消任务的返回结果。取消不结束共享模型进程。

SigLIP 和 Qwen 在应用启动后后台主动加载，并常驻到应用退出，embedding 进程和模型均不因空闲释放。艺术/质量评分模型及其进程仍在空闲 180 秒后释放。正在处理请求期间不会卸载，卸载与新请求之间串行协调。退出应用后管道关闭，子进程退出。

单次请求超时为 180 秒。传输中断/非法响应/进程崩溃会清理该进程，下一个请求自动重新启动；不无限重试失败请求。合法的模型错误（例如损坏图片）返回给当前任务，不为此卸载其他模型。持久评分/向量不会随进程退出丢失。原图/裁剪比较用 `score` 命令，不往图库评分表写候选记录。

## 验证

- `Tests/ModelService/main.swift`：生产调度器的优先级、同级 FIFO、排队/执行中取消、空闲释放、空闲后重建及失败后继续。
- `AI/test_shared_worker.py`：单模型/混合共享、缓存参考图检索不加载、文字缓存共享、跨图库缓存隔离、embedding 常驻及评分运行时过期。
- `AI/verify_shared_models.py art|embedding`：真实模型验证。IAA → IQA → IAA 复用同一模型对象、重复 IAA 分数一致；真实 SigLIP/Qwen 索引与文字查询后，混合检索复用相同对象；缓存参考图无需加载。
- `scripts/test-art-integration.sh`、`scripts/test-similarity-integration.sh`、`scripts/test-photo-editor-integration.sh --real-crop`：通过应用实际调用接口的集成检查。

混合检索分别使用各模型中指纹有效的照片，取结果并集。每张照片对已有模型的 `61 / (60 + rank)` 等权取平均；完整双模型时与原等权 RRF 一致，缺少模型不会被记作零分。以图搜图只使用参考照片具有有效向量的模型；仅一个模型可用时显示其原始余弦相似度。两套索引的 status 仍返回交集，用于判断双模型索引是否完整。
