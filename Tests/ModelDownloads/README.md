# 隔离模型下载模拟

运行：

```sh
zsh scripts/test-model-downloads.sh
```

需要 macOS、Command Line Tools 和系统 `/usr/bin/python3`，不需要真实模型或 AI 虚拟环境。测试需要允许本机监听 `127.0.0.1`。默认不访问外部网络，不执行 pip，不构建或覆盖 `build/PhotoLab.app`。

每次生成独立 `/private/tmp/photolab-model-simulation-*` 目录，其中包含：

- `.photolab-simulation`：隔离目录标记。模拟 App 和安装入口都验证该标记及临时目录前缀，缺失时拒绝运行。
- `PhotoLab Model Simulation.app`：单独的 bundle ID。复用正式模型管理 UI、下载管理器和模型调度器，没有链接图库、照片解码或真实模型推理代码。
- `test_*/`：各场景的独立数据目录、安装日志和合成文件。
- `report.json`：逐项结果、本机服务器请求记录、受保护目录测试前后摘要。
- `server.pid`、编译日志及模块缓存。

默认脚本完成后停止 HTTP 服务；保留临时目录用于核查。可在不需要报告后自行删除该次生成的目录。保护检查只读取路径、大小、模式和修改时间，不读取真实照片或模型内容，也不跟随符号链接。

## 16 项集成场景

1. 拒绝许可、旧权重版本或旧许可确认：不联网，不安装运行环境。
2. 正常安装、重启识别、缓存复用、移动 App 后模拟推理。
3. 取消安装进程并 Range 续传。
4. 强制结束安装进程后恢复。
5. 服务器忽略 Range 时重新下载。
6. 完整文件校验失败后重试。
7. HTTP 503 后重试。
8. 模拟磁盘不足，不下载权重或发布完成记录。
9. 真实 HTTP 连接中断，保留部分文件并续传。
10. 真实 Swift 管理器下载并校验假运行时、安装假模型、通过真实模型调度器调用假推理进程。
11. 安装后文件缺失，不识别为已安装；修复后恢复。
12. 安装记录中的版本、许可或确认状态失效，不识别为已安装。
13. 运行时归档损坏，不解包、不开始模型下载；重试恢复。
14. 运行既有调度器回归，确认配置刷新不会打断在途推理。
15. 不带模拟编译标志的构建仍返回固定官方运行时来源，不读取模拟源。
16. 旧版本地模型没有下载记录时仍被识别，原模型和 Python 路径保持不变，不创建托管模型目录、不联网。

测试文件为 8 MiB 合成字节，测试许可明确写明不构成法律协议。假推理进程通过 JSON 行协议固定返回 `0.42`。依赖安装阶段使用测试替身，不安装或修改现有 Python 环境。

## 手动界面验收

```sh
zsh scripts/test-model-downloads.sh --ui
```

自动测试结束后保持慢速本机服务，控制台打印本次 App 路径和 `PHOTOLAB_DATA_DIR`。在另一个终端使用打印出的临时路径启动其 `Contents/MacOS/ModelSimulation`，不能省略 `PHOTOLAB_DATA_DIR`。然后检查默认禁用的确认按钮、取消确认、下载进度、取消下载及重试。测试许可是假文本，不代表接受任何真实模型协议。

完成后关闭模拟窗口，在运行脚本的终端按 Ctrl-C。最终报告补记手动阶段结束后的保护检查。界面上的官方服务说明沿用正式 UI，但测试传输层只允许本机来源；不要点击模型来源链接，合成模型不对应真实仓库。

## 正式版边界与测试限制

Swift 的本机运行时地址只在 `PHOTOLAB_MODEL_SIMULATION` 编译标志下可用。Python 正式入口没有测试下载源参数或环境变量。测试包使用单独的安装适配器，把正式安装器的 HTTP 调用重定向至本机；适配器不在正式打包资源列表中。

本模拟验证安装状态机、真实网络故障恢复、进程调用和界面；不证明真实 Python wheel、真实模型或 Metal 推理兼容性。发布前仍需在干净机器上做真实模型验收。
